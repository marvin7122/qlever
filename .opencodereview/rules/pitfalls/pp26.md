# PP26: Untrusted workflow code with elevated permissions

## Statement
CI workflows never execute PR head code under `pull_request_target` or write-capable credentials; untrusted checkout and privileged operations are separated and permissions are least-privilege.

## Sources
- review: `.ai-review/personal_pitfalls.md#PP26` Mined from maintainer review comments, file dated 2026-09-22.
- review: `QLever PR #146` "Using `pull_request_target` with the PR head SHA passed to an action that likely checks out code is dangerous ... if the action checks out the PR head code (untrusted), it could execute malicious code with elevated permissions."
