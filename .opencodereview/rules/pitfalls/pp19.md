# PP19: Lifetime-by-design for lazy pipelines (no "probably fine" captures)

## Statement
Any new/changed code that returns a lazy range, view, generator, or deferred lambda is *structurally* free of dangling references: no `[&param]` / `[&local]` into a returned view; only value captures of cheap handles or true ownership (`shared_ptr`/`unique_ptr` of the *resource*, not of a non-owning handle alone). Reject "safe under current join order" as a justification — lifetime must be correct by construction.
