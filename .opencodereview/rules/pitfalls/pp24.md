# PP24: Test-only hooks must not weaken production interfaces

## Statement
Test/benchmark-only mutation and topology injection are isolated from production APIs through test-only hooks, friends, builders, or test-target-only code.

## Sources
- review: `.ai-review/personal_pitfalls.md#PP24` Mined from maintainer review comments, file dated 2026-09-22.
- review: `QLever PR #108` "`setMockTopology` is a public mutator on a production header, but it appears to exist purely for tests/benchmarks. This makes it easy to accidentally depend on in non-test code and weakens invariants of the data structure. Prefer isolating this behind a test-only hook (e.g., `#ifdef AD_TESTING`, a `friend` test fixture, a dedicated builder/test helper in the test target, or moving it to a `.cpp` compiled only into tests/benchmarks)."
- review: `.opencodereview/rule.json#140` QLever OCR fan-out project rule, file dated 2026-09-23.
