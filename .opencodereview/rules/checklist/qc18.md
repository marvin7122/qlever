# QC18: Comments state the non-obvious (preconditions, invariants, why)

## Statement
Comments state the non-obvious (preconditions, invariants, why); name the exact type/entity referred to; claims hold on all branches they cover. Sentences start capitalized. `//___…` separator comments are deliberate style — don't flag.

b [SHOULD] Every new or changed non-void function/method documents what its return value means, including units, ownership or lifetime, and sentinel/empty-value semantics where applicable. Use imperative wording such as "Return the number of bytes written to `out`."
